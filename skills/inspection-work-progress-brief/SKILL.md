# inspection-work-progress-brief

## When to use
在以下场景使用：
- 用户让你“梳理一下当前在推进什么”“总结迎检工作现状”“看看现在主线是什么”
- 工作区里已有多类迎检、整改、演练、汇报、清单材料，但缺少一版清楚的工作判断
- 需要把散乱的专项目录压成 4-6 条主轴，并指出当前最值得盯的焦点

不要在这些场景直接使用：
- 用户只要某一份具体文件的摘要
- 用户明确要逐文件盘点、做台账、做目录清单
- 用户要求的是正式汇报稿而不是工作判断

## Steps
1. 先读取项目级记忆：优先看 `{workspace}/.workbuddy/memory/MEMORY.md` 和最近的日记；如果不存在，明确说明判断将主要基于目录和当前上下文。
2. 查看工作区顶层目录结构，识别主要专项线，例如清朗、关基、反诈、强标、算法/大模型、数据安全、模板库、通用材料库。
3. 检查最近修改的顶层目录，以及与“人才库、专家库、演练、整改、总结、工作说明、总表、协作项”相关的文件名，抓出正在推进的动作面。
4. 不要机械罗列文件。先抽象成 3-6 条主推进线，再为每条线补上对应的目录或文件线索。
5. 单独识别“当前焦点”与“长期底座”两类工作：
   - 当前焦点：现场问题、整改闭环、演练协同、专项报告、口径收口
   - 长期底座：模板库、通用材料库、历史归档、人才/专家库、方法论沉淀
6. 输出时必须先给一句主判断，再写：
   - 当前最核心的推进线
   - 眼下最值得盯的焦点
   - 真实摩擦/风险
   - 建议推进顺序
7. 如果证据主要来自文件命名和目录结构，要写明“这是基于目录与背景做的工作判断，不等同于逐份材料核验结论”。

## Pitfalls
- 不要把“目录里有”直接等同于“当前一定在推进”，要用“更像在推进”“从材料线索看”这类稳妥表述。
- 不要把所有专项平铺罗列成文件清单，重点是抽主轴。
- 不要把迎检专家库写成单纯名单管理，要优先看能力组织、现场支撑和整改跟进界面。
- 若缺少近期日志，不要虚构会议结论、责任分配或具体时间表。

## Verification
- 输出是否能压成 4-6 条清晰主线，而不是一长串目录？
- 是否明确区分了“当前焦点”和“长期底座”？
- 是否给出了真实摩擦与建议顺序，而不只是总结现状？
- 是否引用了少量关键文件/目录作为线索支撑？
