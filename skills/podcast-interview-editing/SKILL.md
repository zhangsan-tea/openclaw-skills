# 播客访谈剪辑 · 人机协作 Harness

> 来源：《WOW时刻》第九期（2:06:13 → 1:13:42，V0.1–V0.8，2026-10）的完整复盘。
> 人读版手册：`https://github.com/zhangsan-tea/openclaw-skills/blob/main/docs/podcast-editing-harness/index.html`
> 本期相关的专有事实（人名、手工剪点、隐私决定）**不在本 Skill 里**，放各期项目目录的 `episode.yaml` 和工作日志。

## 〇、五条铁律（违反任何一条都要停下）

1. **文稿是唯一真相源。** 原始逐字稿做底稿，剪掉的话＝Word 修订删除；“无标记”视图＝成片稿。音频由文稿逐字生成，两者必须逐字一致（G6 校验）。
2. **先确认，再动音频。** 每轮先读回修改 → 出回执表（我怎么理解、准备怎么改，有歧义的标“?”）→ 人确认 → 才剪。人明确说过“直接开始”的，不再重复确认。
3. **读不到就立刻说。** 一旦发现某个通道读不了修订、删除线或批注，**当轮立即停下告知**并给替代方案（见 §三 读取通道表）。禁止先做别的、最后才提。（事故：读不到智能文档批注，几十分钟后才告诉人，人白等。）
4. **每次出片都自检。** 接口重新识别比对；只复核“比上一版新增的”未通过项；每版都量响度、峰值、限幅负担和音色偏差。
5. **音频只能剪，不能改。** 文字只做识别纠错和标点，不增字、不换词。人要的原话节目里没有，就找最接近的一段，并如实说明。

## 一、七道关卡（Gate）

| 关卡 | 动作 | 通过标准 | 禁止 |
|---|---|---|---|
| **G1 决策补齐** | 核对台本是否覆盖全片；列出台本没写清的：说话人标错、会穿帮的话、节目惯例环节；逐项列隐私和带货 | 每处删、留都有人的明确决定；有粗剪时长估算 | 决策没补齐就开剪 |
| **G2 字级对齐** | 本机字级识别 → 和逐行状态表分块对齐 → 对不上的字按前后插值 | 覆盖率 ≥85%；行首偏差中位数 <1s；偏差 >5s 的行逐一解释 | 只用行首秒数剪句中删减 |
| **G3 剪点拼接** | 剪点吸附 10ms 能量最低点；接口 20ms 淡入淡出、补 0.12s；被删部分 <0.35s 不剪 | 文稿每处删除在音频里都确实剪掉 | 手工剪点不登记（必须写进 `overrides`，注明原因） |
| **G4 自检** | 接口前后 ±3.5s 重新识别比对；未通过的拉长到 ±6–8s；本轮改过的地方逐条复听 | 相对上一版**无新增**未通过项，或新增项逐个下了结论（误报 / 已修） | 只报通过率 |
| **G5 母带与音乐** | 用 §四 母带链；转场只放话题转折处 | −16 LUFS ±0.5；峰值 ≤ −1.5 dBFS；音色偏差在阈值内（`scripts/audio_qa.py`）；音乐接口两侧无吞字、无多余空白 | 用单遍动态 loudnorm；用降噪、重压缩 |
| **G6 配套文稿** | 生成同版本号修订稿：删除作者＝谁剪的；每处本轮改动配一条批注；每段开头标成片时间 | 接受全部修订后的字流 ＝ 音频保留字流；作者对得上；批注不落在删除内容里 | 文稿和音频版本号不一致 |
| **G7 交付** | 正式版留本地；另出手机试听版并给链接；回复写清改了什么、重点听哪几个时间点 | 人只看回复就知道结果 | 只给本地路径 |

## 二、每轮固定节奏

读回修改 → 回执表（理解＋改法，歧义标“?”）→ 人确认 → 改音频＋改文稿 → 自检（G4/G5/G6）→ 交付＋试听链接 → 写工作日志（本轮产物、手工剪点、新踩的坑）。

## 三、协作协议

### 3.1 修订稿约定
| 人想做什么 | Word 里怎么做 | 读回时怎么理解 |
|---|---|---|
| 同意删除 | 接受，或者不处理 | 照剪 |
| 恢复 | 拒绝那处删除 | 恢复 |
| 再剪 | 直接删（文档默认打开修订） | 以这个人的名字记为新删除 |
| 听感、说明、疑问 | 批注，不在正文里打字 | 逐条在回执表里回应 |
| 宏观意见 | 在对话里说 | 先确认理解再执行 |

- 删除作者名写版本号（如“剪辑V0.6”），人名写真名，任何时候都能追溯是哪一轮、谁剪的。
- `settings.xml` 里的 `w:trackRevisions` 必须插在 `w:defaultTabStop` 之前，否则 Word 可能报“无法读取的内容”。
- 用户明确说“这次不管修订模式，只按我的批注改”时，只处理新增批注和划线，其余保持上一版不变。

### 3.2 读取通道表（先判断，再承诺）
| 通道 | 删除/新增 | 删除线 | 批注 | 结论 |
|---|---|---|---|---|
| 本地 .docx（含企业微信“导出为 Word”） | ✅ 分得清，带作者 | ✅ | ✅（可能没有选中范围，按划线或相邻句定位，并在回复里写明对应关系） | **首选**，用 `scripts/read_docx_revisions.py` |
| 企业微信在线文档读正文接口 | ❌ 只知道谁改过，分不清删还是加；导入时原修订会丢 | ✅ run 级 strike | ⚠️ 部分 | 只能辅助，**禁止用来推断修订** |
| 企业微信智能文档（smartpage） | — | ⚠️ Markdown 导出不带删除线，要解析块数据的 `attribs` | ❌ 读不到 | 请人用删除线或在文字后写【说明】，**不要用批注**；用 `scripts/read_smartpage_strike.py` |

给人发可编辑文档时，在文档顶部就写清楚：删句用删除线、写说明用【】、不要用批注。

## 四、技术参数

| 环节 | 参数 |
|---|---|
| 字级识别 | `mlx-whisper` large-v3-turbo，`word_timestamps=True`，`condition_on_previous_text=False`，`initial_prompt` 写节目名、人名、术语。模型放 `~/.cache/<name>/`，镜像不稳就改官方源，下载后校验 SHA256 |
| 对齐 | 12 行一块做 `difflib.SequenceMatcher`，ASR 窗口单调推进，匹配块 ≥2 字才采用；同一秒多人说话的按文本相似度分配 |
| 剪点 | 起点在 [−0.35, +0.04]s、终点在 [−0.04, +0.35]s 内找能量最低点，取最低点 3dB 以内离原位最近的 |
| 拼接 | 接口 20ms 淡入淡出；接口补 0.12s；切掉吸气声、残字后单独补 0.40–0.45s |
| **母带链（V0.8 定稿）** | `highpass=f=70` → `volume=8dB` → 削尖峰 `acompressor detection=peak threshold=-16dB ratio=4 attack=1 release=80 knee=6` → 轻慢压 `acompressor detection=rms threshold=-26dB ratio=1.6 attack=30 release=600 knee=8` → 线性增益到单声道 −19 LUFS（≈双声道 −16）→ `alimiter limit=0.80 attack=3 release=80 level=false`。**不降噪、不低通**。函数在 `scripts/master_chain.py` |
| 转场音乐 | 公有领域钢琴（萨蒂《Gymnopédie No.1》Musopen 录音，维基共享资源，无需署名）；每处 5.1s，渐入 0.25s、渐出 1.8s，比人声低 6dB，前后各留 0.25s；每处换不同乐句；约每 10 分钟一处，只放在话题转折处 |
| 开场垫乐 | 钢琴先起 3s；人声进来后压到 −20dB；**句间空档 1.6s**，空档里抬到比人声低约 12dB（每个空档单独算增益）；结尾回升 4s 渐出，停 0.3s 接“大家好，欢迎来到……” |
| 拼接开场 | 开场和正片从原始素材一起处理、一次导出，**不要把两个 MP3 首尾相接** |
| 交付 | 正式版双声道 192k；试听版单声道 160k（74 分钟约 88MB）。企业微信微盘 CLI 上限 100MB；手机链接用 WorkBuddy 资料库上传 |

### 母带链为什么这样定（两次返工换来的）
- **V0.4（单遍动态 loudnorm）**：音色接近原声，但原片轻（约 −28 LUFS）且瞬间峰值高，动态模式随时调增益，个别段被放大 15–19dB 又被硬压，10 秒里上万个采样点被硬压 → **刺啦、电音**。
- **V0.5–V0.7（降噪＋两级重压缩）**：刺啦消失，但句尾回响比原声高约 3dB（像在回音壁里）、2–10kHz 高 2–3dB（发粗）、动态被压掉约 6dB；房间声本来就重的说话人最明显。
- **V0.8（削尖峰＋轻慢压＋兜底限幅）**：回响只比原声高 0.7dB，高频 +1.1～+1.6dB，动态 −2.9dB；原刺啦点前后 10s 内接近满幅的采样点 0–101 个。**这是人认可的状态。**
- 判断音色时一定先**把对比样本调到同样响度**：越响越显得低沉、饱满，不同响度下比较会误判。

### 音色验收阈值（`scripts/audio_qa.py` 对比原片同一段话）
| 指标 | 合格 | V0.7 的值（不合格示例） |
|---|---|---|
| 句尾回响偏差 | ≤ +1.5 dB | +3.0 |
| 2–5k / 5–10k 偏差 | ≤ +2.0 dB | +2.1 / +3.1 |
| 70–200Hz 偏差 | ≤ +1.0 dB | +1.4 |
| 动态范围偏差 | ≥ −4.0 dB | −5.7 |
| 任意 10s 接近满幅（>0.75）采样点 | ≤ 1000 | V0.4 曾超 13000 |

## 五、踩坑清单

| 症状 | 根因 | 对策 |
|---|---|---|
| 几段话里刺啦、电音 | 动态 loudnorm 来回调增益＋硬限幅 | 用 §四 母带链；统计限幅负担 |
| 声音粗、回音大、发闷 | 降噪＋重压缩抬高了房间回响和辅音 | 不降噪；只削尖峰＋轻慢压 |
| 测出来“削波”其实没有 | 两声道相同时 `-ac 1` 下混电平会 ×1.414 | 测峰值取单个声道，或乘 0.707 |
| 转场音乐后吞半个字 | 音乐插在字中间，或剪点落在上一人末字上 | 音乐接口做多候选剪点，逐个识别后选 |
| 接口残留半个字、多一个字 | 对齐误差 0.1–0.3s；逐字稿本身漏字 | 字级时间＋能量包络手工定剪点，登记 overrides；以原音为准 |
| 三人同时说话剪不干净 | 人声叠在一起，物理上分不开 | 只能连带剪或连带留，让人二选一 |
| 自检报大量“待查” | 同音字、识别器重复输出（某词×7）、窗口截断 | 只看新增项；拉长窗口复听后下结论 |
| 中间文件突然没了 | 放在 `/tmp` 被系统清理 | 工作目录放项目内 `_work/`；`/tmp` 只做上传中转 |
| 智能文档导入失败 | CLI 只读工作区和 `/tmp`；文档名不能含 `/` | 先拷到 `/tmp`；标题用“、”代替“/” |
| ffmpeg 滤镜静默输出空 | 参数越界（如 `acompressor knee` 只允许 1–8） | 输出长度为 0 时打印 stderr |
| shell 匹配中文文件名失效 | macOS 磁盘上是 NFD | 一律 Python `os.listdir`＋`unicodedata.normalize` |

## 六、内容判断原则

- **不改原话**：只纠识别错误和标点；可剪的口癖字用〔〕标出，剪掉仍要能听懂。
- **事实要核**：年代、出处要查；音频不改，但字幕和 Shownotes 要写对。
- **隐私与带货**：价格、药名、未征得同意的第三方推荐默认删除；嘉宾家庭和情绪细节由嘉宾本人决定，写进决策表。
- **防穿帮**：暴露录制过程的话（如“怎么收尾？”）要剪；剪掉“第一……”时，要么补回，要么连“第二”一起剪。
- **转场位置**：只放话题真正转换处；连续论述（“第一……第二……”）中间、问答之间不放。
- **节目惯例**：删固定环节前提醒人和主持人打招呼，并保留原始时间方便恢复。

## 七、开场金句（Cold open）

- 三个人都要出声；嘉宾为主，主持人至少各一句。
- **每句补足能单独听懂的前后文**，不要只截金句本身（精简版“听不懂在说什么”）。
- 用跳切穿插，不追求完整故事；最短、最有冲击的一句打头，不铺垫。
- 句间空档 1.6s，空档里音乐抬起，否则几句话会听成一段连续对话。
- 总长约 60–70 秒即可，不必卡死。
- 标注常分散在多份文档里：先合并去重，再列出“标过但没用上的”及原因。
- 方案表固定表头：序 / 开场内时间 / 成片位置 / 时长 / 说话人 / 原话（推荐与备选同一格式）。

## 八、执行清单（每轮照着勾）

**开工前**
- [ ] 输入是 Word 导出还是在线文档？能读到修订、删除线、批注吗？**读不到现在就说**
- [ ] 回执表：位置（成片时间）/ 原意 / 我的改法 / 疑问标“?”
- [ ] 人已确认回执表，或明确说过“直接开始”
- [ ] 工作目录不在 `/tmp`；识别模型在 `~/.cache`

**出片后**
- [ ] 接口自检完成，新增未通过项逐个下结论
- [ ] 本轮改动逐条复听，无残字、吞字
- [ ] 音乐接口两侧单独检查
- [ ] `scripts/audio_qa.py`：响度、峰值、限幅负担、音色偏差都在阈值内
- [ ] 文稿接受全部修订后的字流 ＝ 音频保留字流
- [ ] 音频和文稿版本号一致，文稿首页写“相对上一版改了什么”

**交付时**
- [ ] 手机试听链接
- [ ] 回复：改了什么、重点听的成片时间点、未解决的问题
- [ ] 工作日志：产物、手工剪点、新坑

## 十、脚本

| 脚本 | 用途 |
|---|---|
| `scripts/master_chain.py` | V0.8 母带链：`master(mono_float32, sr)` 返回处理后信号；附响度测量与限幅负担报告 |
| `scripts/audio_qa.py` | 成片音色验收：给原片与成片同一段话的时间，输出各频段、句尾回响、动态范围偏差和合格判定；另报整片每 10 秒限幅负担 |

| `scripts/read_smartpage_strike.py` | 读企业微信智能文档块数据（`pages get content_type=block` 落盘的 JSON），按表格行输出文字，删除线用 `~~ ~~` 标出 |
| `reference/wow9/` | 第九期完整管线的原始脚本（含本期写死的手工剪点），**只作参考实现**，新一期要先抽出参数再用 |
