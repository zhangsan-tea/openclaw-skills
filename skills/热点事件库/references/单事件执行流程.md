# 单事件执行流程（SOP）

> 本文档是「热点事件库」方法论中，处理单个事件的完整标准操作流程。
> 从身份校验到 INDEX 更新，逐步执行，每步通过后再进入下一步。

---

## 流程图

```
身份校验 → 证据闸门 → 建 sources.md → 写 V1 → 写 README → 更新 INDEX → 收录白名单 → 推送工蜂 → 自检
   │            │
   │            └── 未通过 → 只建"证据不足"占位，不做完整 V1
   └── 未通过 → 停止，记录阻塞项，继续下一个事件
```

> 其中「收录白名单」仅适用于**用户点名、原本不在白名单内**的事件：V1 落地后自动收录，无需再向用户确认。

> **「推送工蜂」是强制步骤，不是可选项。** 事件库的**唯一权威存储是工蜂仓库 `git.woa.com/lyndonzhang/obsidian-private`**。任何事件若不 push 到工蜂仓库，后续其他 AI 窗口和 V2/V3 自动追踪必然读不到 V1 基线。

---

## 步骤 A：身份校验

- 核对事件标准名称、发生时间、地点、核心主体。
- 检查是否与同名旧案、相似案件或错误月份混淆。
- 输出「事件身份卡」和初步信源表。

---

## 步骤 B：证据闸门

- 按信源分级（A1/A2/B/C/D）收集证据。
- **身份闸门**：至少 1 个 A1 级，或 2 个相互独立 B 级，确认事件身份与核心事实。
- **完整 V1**：通常累计不少于 5 个相互独立、可访问的有效来源。
- **⚠️ 独立性判定（2026-09-18 补）**：数**原始陈述主体**，不数转载媒体。多家媒体引用同一段口述/同一段视频/同一篇首发报道 = 信源计 1 个。化名不同但措辞雷同的"多位受访者"、以及被逐级放大的场景描述，均不构成独立信源。标"多源一致"前必须能列出至少两个互不隶属的原始陈述主体，否则降级为"单源陈述"。
- **未通过身份闸门**：只做"证据不足"占位，不做完整 V1。

---

## 步骤 C：建立 corpus/sources.md

**先建信源账本，再写报告。**

每条信源记录：
- 标题、发布主体、发布日期、URL、信源等级、支撑事实、访问状态

规则：
- 去重：同一通讯稿的多站转载只算一个原始来源。
- 记录失效、删除、修改、仅有快照等情况。

信源账本模板见 SKILL.md 第十节的目录结构。

---

## 步骤 D：写 V1

固定四段式（详见 SKILL.md 第四节）：
1. 事实剧场
2. 声浪解构
3. 跨学科透视（4 基础维度 + 专属维度 + 治理分级）
4. 语料切片

外加：
- 治理评估（L1/L2/L3，说明证据与判定理由）
- 证据局限（列出尚未确认的问题）

---

## 步骤 E：写 README

只摘要 V1 中已经确认的事实，必须包含：
- 编号、时间、状态、标签、治理等级、文件索引、证据状态

---

## 步骤 F：更新 INDEX.md

- 增加事件表行
- 增加核心矛盾分类和学科视角
- 关联图谱只连接已在白名单或已确认保留的事件
- 不增加"待发现""候选池"或新的扩散选题
- 文件存在但证据未通过的事件，状态写"⚠️ 证据待审"，不得写"V1 完成"

---

## 步骤 F2：收录白名单（用户点名事件）

**适用于用户点名、原本不在白名单内的事件**：

- V1 落地后，**自动**按「月份 + 顺序」把该事件追加进白名单，分配 `EVT-YYYYMM-NNN` 编号。
- 同步更新项目事件索引，保持白名单与 INDEX 一致。
- **无需再向用户确认"是否收录"**——白名单是去重清单，凡用户指示新增的事件，V1 完成即自动入库。

---

## 步骤 F3：推送工蜂（强制 · 事件库唯一权威存储）

**事件库的唯一权威存储是工蜂仓库 `git.woa.com/lyndonzhang/obsidian-private`。** 每个事件在本地落盘后，**必须** push 到工蜂仓库的 `舆情热点/` 目录，否则后续其他 AI 窗口与自动任务（V2/V3）在独立沙箱中无法读取。

### 权威路径

| 项目 | 值 |
|------|-----|
| 仓库地址 | `git.woa.com/lyndonzhang/obsidian-private` |
| 事件目录 | `舆情热点/YYYYMM-事件简称/` |
| 事件索引 | `舆情热点/_index.md` |
| 提交身份 | `lyndonzhang <lyndonzhang@tencent.com>` |

### 推送动作

1. 在 `舆情热点/` 下创建事件同名目录（`YYYYMM-事件简称`），放入 README.md、V1 文件、corpus/sources.md（及 quotes.md）。
2. 更新 `舆情热点/_index.md`（追加事件行、分类索引）。
3. 使用工蜂连接器，以 `lyndonzhang <lyndonzhang@tencent.com>` 身份 commit 并 push 到工蜂仓库。
4. 推送后事件即可被其他 AI 窗口与自动任务通过工蜂连接器 clone/pull 读取。

### 铁律

- ❌ **禁止只写本地 `/tmp` 而不 push 工蜂**——这会导致后续窗口与自动任务找不到 V1。
- ❌ **禁止在自动任务 prompt 中写死本地路径**（如 `/tmp/obsidian-private/...`）——自动任务沙箱没有本地文件。自动任务 prompt 必须引用**工蜂仓库路径**（`舆情热点/YYYYMM-事件简称/`），并通过工蜂连接器 clone/pull 读取。
- ✅ 本地工作区可保留一份副本用于编辑，但**权威落盘以工蜂仓库为准**。

---

## 步骤 G：自检

逐项检查：
- [ ] 事件在白名单吗？（用户点名事件：V1 后已自动收录）
- [ ] **事件已 push 到工蜂仓库 `lyndonzhang/obsidian-private` 吗？（强制）**
- [ ] **INDEX.md 已 push 到工蜂仓库吗？（强制）**
- [ ] 核心事实有来源吗？
- [ ] 是否把推测写成事实？
- [ ] 是否出现无法定位的引语？
- [ ] 是否错误创建了 2025 年 V2？
- [ ] INDEX、README、V1、sources 状态一致吗？

通过后才能标记完成。

---

## 证据不足时的处理

当无法建立可靠事实链时：
1. 立即停止扩写，不得用常识补齐。
2. 记录为阻塞项（列出：已搜索关键词、找到的材料、缺口、下一步需要的证据）。
3. 继续处理白名单中的下一个事件。

> **文件写出来 ≠ 研究完成。证据闸门通过才等于完成。**
