# 单事件执行流程（SOP）

> 本文档是「热点事件库」方法论中，处理单个事件的完整标准操作流程。
> 从身份校验到 INDEX 更新，逐步执行，每步通过后再进入下一步。

---

## 流程图

```
身份校验 → 证据闸门 → 建 sources.md → 写 V1 → 写 README → 更新 INDEX → 自检
   │            │
   │            └── 未通过 → 只建"证据不足"占位，不做完整 V1
   └── 未通过 → 停止，记录阻塞项，继续下一个事件
```

---

## 步骤 A：身份校验

- 核对事件标准名称、发生时间、地点、核心主体。
- 检查是否与同名旧案、相似案件或错误月份混淆。
- 输出「事件身份卡」和初步信源表。

---

## 步骤 B：证据闸门

- 按信源分级（A1/A2/B/C/D）收集证据。
- **身份闸门**：至少 1 个 A1 级，或 2 个相互独立 B 级，确认事件身份与核心事实。
- **完整 V1**：通常累计不少于 5 个相互独立、可访问的有效来源。
- **未通过身份闸门**：只做"证据不足"占位，不做完整 V1。

---

## 步骤 C：建立 corpus/sources.md

**先建信源账本，再写报告。**

每条信源记录：
- 标题、发布主体、发布日期、URL、信源等级、支撑事实、访问状态

规则：
- 去重：同一通讯稿的多站转载只算一个原始来源。
- 记录失效、删除、修改、仅有快照等情况。

信源账本模板见 SKILL.md 第十节的目录结构。

---

## 步骤 D：写 V1

固定四段式（详见 SKILL.md 第四节）：
1. 事实剧场
2. 声浪解构
3. 跨学科透视（4 基础维度 + 专属维度 + 治理分级）
4. 语料切片

外加：
- 治理评估（L1/L2/L3，说明证据与判定理由）
- 证据局限（列出尚未确认的问题）

---

## 步骤 E：写 README

只摘要 V1 中已经确认的事实，必须包含：
- 编号、时间、状态、标签、治理等级、文件索引、证据状态

---

## 步骤 F：更新 INDEX.md

- 增加事件表行
- 增加核心矛盾分类和学科视角
- 关联图谱只连接已在白名单或已确认保留的事件
- 不增加"待发现""候选池"或新的扩散选题
- 文件存在但证据未通过的事件，状态写"⚠️ 证据待审"，不得写"V1 完成"

---

## 步骤 G：自检

逐项检查：
- [ ] 事件在白名单吗？
- [ ] 核心事实有来源吗？
- [ ] 是否把推测写成事实？
- [ ] 是否出现无法定位的引语？
- [ ] 是否错误创建了 2025 年 V2？
- [ ] INDEX、README、V1、sources 状态一致吗？

通过后才能标记完成。

---

## 证据不足时的处理

当无法建立可靠事实链时：
1. 立即停止扩写，不得用常识补齐。
2. 记录为阻塞项（列出：已搜索关键词、找到的材料、缺口、下一步需要的证据）。
3. 继续处理白名单中的下一个事件。

> **文件写出来 ≠ 研究完成。证据闸门通过才等于完成。**
