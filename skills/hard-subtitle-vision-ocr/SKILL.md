# 视频硬字幕 OCR 提取

## When to use

- 用户给出本地或可下载视频，要求提取完整字幕，且视频没有可直接获取的 CC/SRT 字幕。
- 已抽样确认字幕被烧录在画面中，尤其适用于中文课程、讲座、访谈和录屏。
- 运行环境为 macOS，能够调用 `ffmpeg`、`swiftc` 和 Apple Vision。

不要用于：没有硬字幕的视频（改用 ASR）、字幕位置持续变化的视频、或必须达到逐字司法级精度的场景。

## Steps

1. **先确认来源而非直接全量跑**
   - 检查视频时长、分辨率、已有 CC 字幕。
   - 在不同时间点抽 3-5 帧，确认硬字幕是否贯穿全片、位置和高度是否稳定。
   - 通过多时点长句样本标定“恰好覆盖字幕、排除固定背景文字”的最小有效裁切区域；不能机械只截中央 320 像素（会截断长句），也不能盲目取整行画面（会把板书、水印等背景文字混入）。

2. **建立 Apple Vision 批量 OCR helper**
   - 以 Swift 的 `VNRecognizeTextRequest` 识别 `zh-Hans`，`recognitionLevel = .accurate`、`usesLanguageCorrection = true`。
   - helper 应支持输入目录、按图片文件名排序、逐行输出 `文件名<TAB>识别文本`。一次处理一个目录，避免为每一帧启动一次 OCR 进程。
   - 使用 `swiftc -O` 编译；先对包含专名和长句的字幕帧做验收。

3. **按小段逐秒抽帧并转写**
   - 以 30 分钟为推荐分段，逐秒抽帧（`fps=1`），每段独立输出一个 SRT。
   - 临时帧可放系统临时目录；Apple Vision 能稳定读取该目录。不要在脚本收尾批量删除成千上万帧，以免触发宿主安全中断。
   - 使用已标定的最小有效字幕区，不把“整行画面宽度”等同于字幕宽度。抽帧和 OCR 完成后才能原子写入段 SRT，避免中断留下半成品。
   - 相同字幕跨连续帧只保留一条，并把显示时间延长；比较时忽略标点与空白差异。

4. **合并后必须做第二校对**
   - 不得把逐秒 OCR 的首次 SRT 直接交付。逐秒采样会引入短暂的单帧误识、短空档后的重复字幕，以及字幕框外噪点被拼成尾字。
   - 以时间相邻上下文做保守清理：合并无有效中间字幕的短间隔同句；消除 `A-B-A` 型单帧抖动（`B` 与 `A` 高相似且只持续约一秒）；删除“长句 + 空格 + 单个尾字/字母”这类孤立 OCR 噪点。
   - 视频若同时展示经页、幻灯片或书页，固定页眉/章节名可能与底部字幕落入同一裁切区；全片统计高频固定短语（例如“……分 第……”的章节标题），结合原帧证明后单独执行“固定文字清理”。该清理必须只移除已验证的画面固定文字，保留来源 SRT，并为每条改动记录时间、前后文本与规则。
   - 原始 OCR SRT 必须保留；第二校对版另存，并输出可审计的规则、数量、前后文本记录。不要用自动规则改写实质不同的相邻语句。

5. **可续跑调度**
   - 全片调度器逐段执行；若分段 SRT 存在且含时间轴，则跳过。
   - 每段完成后更新 `进度.txt` 和运行日志；所有分段完成再合并并重编号为完整 SRT。
   - 运行中断时不要重下视频，不要覆盖已完成分段；重启同一调度器即可续跑。

6. **质量复核与交付**
   - 随机检查开头、中段、结尾，以及人名、术语、长句是否被截断。
   - 说明硬字幕 OCR 的边界：单字形近误识、断句、标点缺失仍可能存在。对关键术语应做人工/上下文校正。
   - 交付完整 SRT；如用户需要阅读稿，再单独按语义段落整理，不能把未经清理的 OCR 直接当讲义。

7. **需要转成长文阅读稿时**
   - 以已通过质量复核的终稿 SRT 为正文来源，去除时间轴和序号；不得摘要化、重排讲者论证顺序或把口语擅自改写成书面论述。
   - 利用“固定文字清理审计”中保留的章节页眉及其首次出现时间，回收可验证的章节标题，再按视频真实时间排序；讲座未必遵循经文的规范 1→32 顺序，不能强制按章号重排。
   - 只在可确认标题处设章；未能可靠回收的章节保持连续语义段落，不编造标题。标点恢复必须以连续文本块为输入，不能把每一帧字幕切换机械等同于逗号或句号；再按完整句子压成适合手机阅读的短段。
   - 对长文输出做结构复核：确认无时间轴、无段首标点、无重复标点；统计段落长度（目标约 90–170 字）、句号/问号密度与超长句比例，并抽检开头、中段、结尾的朗读连贯性。
   - 同时输出 Markdown 便于后续编辑、HTML 便于阅读和目录跳转；HTML 需在对话中直接预览。

## Pitfalls

- B 站视频可能没有 CC 字幕但存在硬字幕；必须先查接口再抽帧确认，不能把两种字幕混为一谈。
- `tesseract <image> -` 在某些环境下会把输出参数解析异常；优先使用 Apple Vision，或显式使用 `stdout`。
- PNG 的批量抽帧在部分 ffmpeg 配置中会失败或产生不可读文件，JPG 更稳。
- 只裁剪中央 320 像素会截断长字幕；反过来盲目裁整行宽度也会把固定板书、水印或背景字混入正文。必须以短句、长句和空字幕帧共同标定最小有效区域。
- 逐帧 OCR 不只会因标点产生相邻重复：还会出现 `A-B-A` 单帧抖动、短空档后同句重现、以及字幕框外内容被误拼为单个尾字。首次 OCR 必须经过第二校对，不能只依赖逐帧的精确字符串比对。
- 视频与原始素材体积大，不要纳入 Git；将脚本和小体积 SRT 分开管理。

## Verification

- 单段试跑至少 120 秒，检查输出含连续 SRT 序号、时间轴和非空字幕。
- 手工核验至少 5 个时间点，覆盖短句、长句、佛学/专业术语和人名；另对全片执行异常扫描，重点标记拉丁字母前缀、异常短句、孤立单字、相邻重复与 A-B-A 抖动，回看原始帧确认后再交付。
- 检查 `进度.txt` 中已完成分段数能递增；中断后再次启动，确认已完成分段被跳过。
- 全片合并后确认 SRT 序号从 1 连续、末尾时间接近视频总时长。
