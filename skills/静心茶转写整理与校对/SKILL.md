# 静心茶转写整理与校对 Skill

**一个 Skill 覆盖「转写 → 入库 → 校对 → 清单」全链路。**

> ⚠️ 本 Skill 由原 `静心茶转写整理` 与 `静心茶转写校对` **两个 Skill 于 2026-09-20 合并而成**。
> 合并原因：两者各自写了一份版式规则，且**互相矛盾**（一边要求保留 `**中脉空间**`，一边要求取消它），执行时无从取舍。
> **版式规则在本文件内只此一份（第 1 节），任何其他位置不得另写版式。** 修改版式只改第 1 节。

## 0. 固定五步流水线（不跳步）

用户常在一次任务里说「入库和校对」，两件事连着做，顺序固定：

| 步 | 动作 | 产物 | 所属阶段 |
|---|---|---|---|
| 1 | 拉取录制与转写 | `/tmp/st_full_YYYYMMDD.json` | A 整理 |
| 2 | 生成入库稿 | `练习记录/YYYYMMDD_静心茶练习.md` | A 整理 |
| 3 | **立刻备份 + md5 双向校验** | `练习记录/校对前备份/YYYYMM/` | A 整理（收尾） |
| 4 | 五层互检 + 标点分段优化 | 就地改**入库稿** | B 校对 |
| 5 | 四节式清单 + 自检 | `练习记录/校对记录/YYYYMM/*.changes.md` | B 校对（收尾） |

**只做校对时**从第 3 步起；**只做入库时**到第 3 步止。两阶段共用第 1 节的版式与第 10 节的自检。

## 1. 唯一版式规范（不可更改项）

> 落笔前**先跑一次库内统计再动手**，不要凭记忆：
> ```bash
> cd "/Users/lee/obsidian-private/向内看/静心茶/练习记录"
> for f in *_静心茶练习.md; do sed -n '2p' "$f"; done | sort | uniq -c | sort -rn | head
> ```

### 1.1 文件命名与 frontmatter

- 文件名：`YYYYMMDD_静心茶练习.md`（如 `20260810_静心茶练习.md`）
- 目标目录：`/Users/lee/obsidian-private/向内看/静心茶/练习记录/`

```yaml
---
date: YYYY-MM-DD
source: 腾讯会议转写
meeting: 21日静心茶营
type: 练习记录
auto_generated: true
---
```

### 1.2 正文骨架

```markdown
# 21日静心茶营 · M月D日

来源：腾讯会议自动转写，AI 整理格式。

---

**Bommie**：
（英文段）

**中脉空间**：
（中文段）

**Bommie**：
（英文段）

**中脉空间**：
（中文段）
```

- **中英逐段交替**：英文原文段 → 中文口译段，交替出现，**不可省略英文**，也不要纯中文或纯英文输出。
- **双标签**：`**Bommie**：`（波密英文原声）+ `**中脉空间**：`（庄西中文口译）。
- **标签独占一行**（换行式）为**目标形态**；`**Bommie**：内容`（**行内式**）同属合法变体——两种形态下游解析正则一致（`^\*\*([^*\n]+?)\*\*[：:]`），**不必强行改写**，也不因此重排全篇。
- **不要**为了省 token 过滤英文内容；段落数与原始转写段落数应一致。

#### 库内实测形态分布（2026-09-20 普查 111 篇）

| 形态 | 篇数 | 说明 |
|---|---|---|
| **双标签**（目标） | **65** | 含换行式与行内式两种排版 |
| 单标签（`**Bommie**：` 块内「英文 + 空行 + 中文」，中文不单独标人） | 46 | 7 月录播场（`**Elsa**`）+ 8 月下旬 4 篇 + 20260915 等 |

**8 月 5 日起口径**：30 篇双标签 vs 5 篇单标签 ⇒ **双标签是现行主流，作为新稿目标**。
⚠️ 旧稿（尤其 7 月 `**Elsa**` 录播场、0822–0825、20260915）**保持原形态，不转换**——「不加原文没有的内容」优先级高于版式统一。

### 1.3 说话人标签判定（按语种，**不按编号**）

| 标签 | 实际含义 |
|---|---|
| `**Bommie**` | 波密英文原声（加工稿中由人工标注补出） |
| `**中脉空间**` | **共用会议账号名**；块内中文＝庄西口译，未加工稿里英文也归在此名下 |
| `**Elsa**` | **录播播放账号**——整场录播由同修艾莎播放，转写把全场音频归到她名下 |
| `**艾莎**` | 同修本人发言（重庆同修、学员身份，兼录播/共享音频操作人） |
| 学员真名（`**夜子：**`／`**利军：**`…） | 学员独立声纹识别出的真实姓名，直接用 |

**判定规则（只有三条）**：

1. `speaker.user_name` 以 `中脉空间` 开头（三种形态都要覆盖：`中脉空间`、`中脉空间-发言人N`、`中脉空间 共享音频`）→ **按段落语种定**：
   ```python
   en = len(re.findall(r"[A-Za-z]", t)); zh = len(re.findall(r"[\u4e00-\u9fff]", t))
   label = "Bommie" if en > zh else "中脉空间"
   ```
   中英混说段（如「啊，所以所以。Halfway in the circle.」）以多数语种为准。
2. `speaker.user_name` 是「学员名 + `-发言人N`」→ **剥掉 `-发言人N` 取基础人名**（同一人的两个编号是声纹切分，不是两个人）。
3. `speaker.user_name` 是具体人名（夜子／利军／谷雨／路翠Lucy／Elsa.艾莎）→ 直接用该人名，**不改写、不并入老师段**。

⚠️ **`发言人1` / `发言人2` 的编号随「谁先开口」翻转，场次之间可以完全相反**（实测 20260914 是 1=英文、20260917 是 1=中文；20260919 同一账号内英文中文交错，编号与语种无稳定对应）。**绝不可按编号机械映射。**

**标签一律不改**：不做「Elsa 场重标为 Bommie/庄西」这类机械改写——同一标签在录播场指账号、在交流场指真人，机械改写必然出错。

### 1.4 段落长度上限

| 段落类型 | 上限 | 说明 |
|---|---|---|
| 中文段（纯练习稿） | **≤150 字**（容差 170） | 库内实测 39–81 字 |
| 中文段（交流/分享段） | **≤150 字** | 库内分享日稿最长 151 字；超长块必须按语义拆（见 §3.2C） |
| 英文段 | **不适用 150 字上限** | 库内英文单行最长可达 610 字符，属正常；以「手机阅读不滚屏」为准，约 ≤3–4 行 |
| 音译 / 梵呗 / 唱诵段 | **整段不拆** | 如 20260719 的 229 字《心经》音译段；须在清单说明 |

150–170 字之间的残留段按上限保留时，**必须在清单写明**：段首内容定位 + 字数 + 不可拆原因。

### 1.5 空白帧与事件提示

- 只有 `。` 的空白帧 → 改为括注 `（此处无清晰内容）`，**不删整轮**。
- 转写系统事件提示（如 `共享音频`）→ 改为括注 `（共享音频）`，不留作独立成行的正文；歌词段不并入该行，原样保留为下一段。

## 2. 阶段 A · 整理入库

### 2.0 授权（每次开工先做）

```bash
tmeet auth status
```

- `Not logged in` → 执行 `tmeet auth login --no-browser`，把打印的 `authorize url` 交给 Lee 确认。
- 报错 `file lock timeout (5s): ~/.tmeet/token.lock` → 上次登录进程残留，`rm -f ~/.tmeet/token.lock` 后重跑。
- 凭证失效迹象：`~/.tmeet/config.json` 缺失、`~/Library/Application Support/tmeet/` 下只剩 `.enc.lock` 没有 `.enc`。
- 排查线索：`~/.tmeet/logs/tmeet-YYYY-MM-DD.log` 记录 `auth logout`、超时等事件——凭证被静默清空时先查这里。
- 授权成功后 `tmeet auth status` 显示 `Logged in` + OpenId + UserName；AccessToken 约 6 小时、RefreshToken 约 30 天。
- **Skill 内不保存 token**，不写死用户目录与旧脚本路径。

#### ⚠️ 2026-09-21 实测纠正：**必须前台跑 login，后台跑会白点**

旧版本节建议「挂后台续期循环」，**实测无效，已推翻**：后台（`nohup … &`、脚本内子 shell、`script` pty 均试过）启动的 `tmeet auth login` 虽能打印 `authorize url`，但 **Lee 在浏览器点完显示「授权成功」后，`auth status` 仍是 `Not logged in`，`~/.tmeet/` 里始终不出现凭证**——因为后台进程脱离控制终端，OAuth 回调写不回本地。也试过 tmux（本机未装）。

**有效做法：前台直接跑，让它阻塞等待（最长 300s）。**

```bash
tmeet auth login --no-browser     # 前台执行，会打印 authorize url 后阻塞 waiting for authorization...
```

- 用 Bash 工具**前台**执行并给足 `timeout`（如 45–60s）；工具超时后会自动转后台，此时 URL 已在输出里，把链接给用户点即可。
- 用户点完若凭证已落盘，再跑一次会返回 `Error: user has been login, please use 'tmeet cmd [flags]' to use` —— **这是成功的信号**，立刻 `tmeet auth status` 确认。
- 链接有效期约 5 分钟。过期就 `pkill -f "tmeet auth login"` + `rm -f ~/.tmeet/token.lock`，再前台跑一条新的。
- 判死标准：浏览器说成功但 `auth status` 仍 `Not logged in` → 一定是**本机没有前台进程在等**，不是授权失败。

#### tmeet 不在 PATH 时（换新会话／环境重置后常见）

`tmeet` 不是系统自带，由 WorkBuddy 连接器提供，包名为 `@tencentcloud/tmeet`（见 `~/.workbuddy/connectors-marketplace/connectors/tmeet/cli.json`）。`which tmeet` 为空时**装到独立空目录**，不要装进 `~/.workbuddy/binaries/node/workspace`（已有 node_modules 会 ENOTEMPTY + BROKER_DENY 失败）：

```bash
mkdir -p /tmp/tmeet-cli && cd /tmp/tmeet-cli && npm install @tencentcloud/tmeet
# 固化到持久目录，后续用完整路径调用
mkdir -p ~/.workbuddy/binaries/node/tmeet-cli && cp -R /tmp/tmeet-cli/node_modules ~/.workbuddy/binaries/node/tmeet-cli/
T=~/.workbuddy/binaries/node/tmeet-cli/node_modules/.bin/tmeet   # v1.0.18
```

`tmeet` 连接器在 WorkBuddy 里显示 connected 时，PATH 里通常已有
`~/.workbuddy/binaries/node/cli-connector-packages/bin/tmeet` —— **优先用 `command -v tmeet` 拿到的那个**，
只有查不到时才走上面的安装流程。两种情况凭证目录都是 `~/.tmeet/`，可共用。

凭证目录 `~/.tmeet/` 与安装位置无关，重装 CLI 不影响已登录状态（若 `~/.tmeet/logs` 还在，说明之前装过）。

### 2.1 查询录制列表

```bash
tmeet record list --start "2026-09-01T00:00:00+08:00" --end "2026-09-30T23:59:59+08:00" --format json
```

- **日期必须是 RFC3339 完整格式**（`2026-09-01T00:00:00+08:00`）；只给 `YYYY-MM-DD` 会报 `--start format error`。
- 返回路径 `data.record_meetings[].record_files[]`，取 `record_file_id` 与 `meeting_id`。
- 一场会议通常有 **2 条 `record_files`**：会前短片段（0–6 分钟、几 MB）+ 正片（45–130 分钟、几百 MB）。按 `record_start_time` 升序，**取时长覆盖完整会议的那条**。会前短片段常已被删除，拉取时报 `error_code 4051 录制文件已经被删除`，跳过即可。

#### ⚠️ 录制「查不到」≠「不存在」——转码与可见有延迟，隔日必须复查

**实例**：9/16、9/18、9/19 三天在 9/18 早间按会议号全类型搜索 + 逐日复核均为 **0 场**，曾被判定「无云端录制」；9/20 早间再查**三天全部出现**，且 `state_int = 3（转码完成）`。

**铁律**：

1. **绝不下「这几天没有录制」的结论**。查不到只说明**此刻**不可见。
2. 补录任务中若有「今天/昨天」的场次缺失，先记为**待复查**，**次日再查一次**，不要写进「不要再试」的清单。
3. 查录制前先核 `state_int`：`3` = 转码完成可拉转写；未完成的场次等下一轮。
4. 一次把搜索窗口放宽到**目标日 ±7 天**，把已在库/未在库的所有静心茶场次一次列全，再按日期差集找缺口——比逐日单查更省调用，也不会漏掉延迟可见的场次。

### 2.2 获取转写（**两步，不可省**）

**第一步：拿段落索引与总段数**

```bash
tmeet record transcript-paragraphs --record-file-id "<fid>" --meeting-id "<mid>" --format json
```

返回 `data.pids[]` 与 **`data.total`**（总段数）。**这一步拿不到任何正文文字**——只用来确定 `total`。

> ⚠️ 常见误判：直接拿这个接口的结果去数段落，会得到「0 段」的错觉（它没有 `minutes.paragraphs` 字段）。正文必须走第二步。

**第二步：按 `pid` 拉正文**

```bash
tmeet record transcript-get --record-file-id "<fid>" --meeting-id "<mid>" \
  --pid "0" --limit "<total + 10>" --format json > /tmp/st_full_YYYYMMDD.json
```

- `--limit` 给 `total + 10` 可**一次拉全**（实测 516 段的场次一次到位）。
- 若取回的 `paragraphs` 数 < `total`，退化为**分批循环**：`--pid` 从 0 起，每次 `--limit 50`，累加结果。
- 合并成一次 `--pid 0 --limit 250` 也能拿前 250 段，但**长场次（如 128 分钟 / 516 段）会截断**——先取 `total` 再定 `--limit`。

**转写数据结构**：

```text
data.minutes.paragraphs[].speaker.user_name
data.minutes.paragraphs[].sentences[].words[].text
```

- 每个 `paragraph` 含说话人与多个 `sentence`；**必须按 `speaker.user_name` 保留说话人边界**。
- 文本拼接：`sentences[].words[].text` 顺序拼接后 `strip()`；空段落写 `（此处无清晰内容）`。
- Bommie 英文段后应紧跟对应的中文段；不得因批处理删除英文内容。
- 只有单语、缺少口译或说话人标记的录制，**不强行补译**，在清单列「待人工确认」。
- 老师与学员共用账号时，学员**只有独立声纹**才会被识别出真实姓名，否则被并进 `发言人N`。逐场核一下非老师标签数量，异常为 0 时在清单记一句。

### 2.3 生成入库稿（脚本机械映射）

**入库稿必须忠实于原始转写，不改字**——错字留给阶段 B 校对处理（这样清单才有前后对照）。

**Token 控制（硬性）**：单日转写 JSON 约 120KB、可能超 50K token。

1. 用 Bash 管道 + Python 解析 JSON、生成 Markdown，**绝不把原始 JSON 读进上下文**。
2. 每次只处理一天。
3. 直接写文件，**不回显完整内容**。

```bash
P=/Users/lee/.workbuddy/binaries/python/versions/3.13.12/bin/python3
# 1. 先取 total（此步无正文）
tmeet record transcript-paragraphs --record-file-id "<fid>" --meeting-id "<mid>" --format json \
  | $P -c "import json,sys; print(json.load(sys.stdin)['data']['total'])"
# 2. 再按 pid 拉正文到临时文件
tmeet record transcript-get --record-file-id "<fid>" --meeting-id "<mid>" \
  --pid "0" --limit "<total+10>" --format json > /tmp/st_full_YYYYMMDD.json
# 3. 解析 data.minutes.paragraphs，按 §1.2 版式写目标 md
```

### 2.4 平台屏蔽词与掩码（落 Markdown 前必须清除）

原始 JSON 中部分词被平台替换为字面量，**落到 Markdown 后会破坏强调语法或留下噪声**：

| 形态 | 实测出现位置 | 处理 |
|---|---|---|
| 字面量 `**` | 身体词位置（会阴、乳头等） | 按**同段中文口译** + 上下文还原为正常英文单词 |
| `%!X(MISSING)`（如 `65-70%!。(MISSING)`、`100%!w(MISSING)ith`、`25%!o(MISSING)f`） | 百分号/数字与后续字母连读 | 按同段中文口译还原为 `65% 到 70%`、`100% with`、`25% of`，并核对数字与中文一致 |

- 两种掩码都要在清单「修改记录」标注（如「屏蔽补出」），并在「待确认」写清「原文为 `**`／`(MISSING)`，还原属推断」。
- **成品内不得残留**（自检项：`**` 掩码 = 0、`(MISSING)` = 0）。

## 3. 阶段 B · 校对

### 3.1 五层交叉互检模型

#### Layer 1：音转文硬伤（英文方向）

| 类型 | 示例 | 修正 |
|---|---|---|
| 语音听错词 | Dogs → Thoughts | **Thoughts** |
| 介词听错 | Two silence → **to** silence | **to** |
| 近音词混淆 | science → **silence**；common thing → **commenting** | 按语境 |
| 拼写/大小写 | if / i / who with | **If** / **I** / **with** |
| 重复词 | when that when that | when that |

**规则**：只改语音识别明显错误，不改原意修辞。

#### Layer 2：中文反推英文（中文方向）

用中文语义反推英文断句与标点：

- 英文句号位置是否导致语义断裂；
- 英文是否遗漏被转写「吃掉」的片段；
- 英文断句是否错位（`Then even your speech. Will become...` → `Then even your speech will become...`）。

**规则**：以中文翻译的完整性为准，反推英文断句是否合理。

#### Layer 3：正念语义校准

- **术语准确性**：stage vs state；mere 是否应为 meditative/inner/here。
- **逻辑自洽性**：上下文是否连贯、概念是否完整。
- **三要素完整性**：如「三件事」是否清晰列出（意图→放松→沉入空无）。
- **前后呼应**：同一概念在不同段落表述是否一致。
- **立场校准（批评 vs 倡导）**：见下。

**规则**：不改动波密原意，只做使语义更准确的微调。

##### ⚠️ 立场校准：中文转写极易把「批评/提醒」写成「倡导」

中文转写常**缺失否定词或质疑标记**，导致波密**揭露并质疑**某机制的句子读起来像在**倡导**它。这是危害最大的一类错误——会把修习指引直接反转。

**判据**：看后续句是否有反问或否定收尾。有反问/否定 → 前文是批评，不是倡导。

| 位置 | 英文 | 中文转写（错误） | 正确理解 |
|---|---|---|---|
| L615 | But to actually justify a justification | 而是合理化，我们的合理化 | 波密在**揭露**头脑层层加固的机制，非倡导 |
| L623 | to protect ourselves stronger **as a concept** | 更强烈地保护我们自己 | 丢了「作为一个概念」这个关键限定 |
| L627 | But is that protection **truly taking place**? | 而这个保护足够吗？真正的在发生吗？ | 反问＝质疑态度所在 |
| L631 | Meditation is not keen on justification | 静心感兴趣的并不是合理化 | 否定收尾，坐实前文为批评 |

**处理**：必须补上明确的提醒语气（如「可这份保护真的在发生吗」「静心感兴趣的从来不是合理化」），把态度立住。

**同类陷阱——头脑的代言句**：波密常引用「头脑对我们说的话」来示范伪装，这类句子必须标记说话主体，否则会被读成波密本人的建议。
- 原文：`The mind disguises as something else. We have to learn more, we have to get more opinions. But in the end, it's fear.`
- 中文：`我们要学更多，我们要获得更多的意见，但最终是恐惧。`
- 修正：加「**它说**」→ `头脑会把它伪装成别的样子，它说：你要学更多，你要获得更多的意见。但最终，它还是恐惧。`

#### Layer 4：修辞保留确认（**不可改动**）

| 修辞类型 | 示例 | 处理 |
|---|---|---|
| 动词排比 | **watch, to observe** | 保留并列，不合并为单一词汇 |
| 不定式排比 | **Not to struggle, not to try** | 保留不定式结构 |
| 名词排比 | **the system of expression, the system of watching...** | 保留重复结构 |
| 排比问句 | **Is it silence, or is it impatience?** | 保留重复句式 |
| 短句重复 | **An expression of silence. An expression of listening...** | 保留短句节奏 |

这些是波密的表达风格，**只标注、不改动**。

#### Layer 5：输出标记

| 标记 | 含义 | 场景 |
|---|---|---|
| `(音转文修正)` | 语音识别明显错误 | Dogs→Thoughts、Two→to |
| `(断句修正)` | 标点或断句调整 | 句号位置、合并被断开的句子 |
| `(语义校准)` | 使语义更准确 | stage→state、补全遗漏概念 |
| `(修辞保留)` | 虽有疑问但保留原文 | watch/observe 排比、mere 存疑 |
| `(待确认)` | 语义存疑，需人工复核 | 无法判断的发音混淆 |

#### 执行顺序

```
Step 1 通读全文，标记明显音转文硬伤（L1）
Step 2 逐段中文反推英文，检查断句与标点（L2）
Step 3 从正念语境检查术语与逻辑（L3）
Step 4 确认波密修辞未被改动（L4）
Step 5 标点与分段优化（§3.2）
Step 6 保真率校验（§3.3）
Step 7 输出校对后正文 + 四节式清单（L5）
```

> 五层校对与标点分段优化可在同一次处理中完成，但**判断标准不同**：五层只做「可确认的纠错」，标点分段是「按语义重新断句分段」。**不要把标点调整记进「修改记录」冒充纠错。**

### 3.2 第二轮：标点与分段优化（必做）

转写稿的标点按字幕帧边界生成，不是按语义生成。五层校对完成后必须再过一遍，否则成品无法正常阅读。

#### A. 标点按语义重整

| 问题 | 处理 |
|---|---|
| 整段几百字全是逗号、没有句号 | 按完整语义单元收句号，不要让全段靠逗号串起来 |
| 「一帧一行」，语义上同一句被切成两行 | 合并为一句，用逗号/分号连接，不必保留原帧切分 |
| 原在同一行但语义独立 | 用句号断开 |
| 中文词间用空格代替标点或纯属多余 | 删空格补标点（`希望 你休息好了` → `希望你休息好了`） |
| 游离句号残留（`. 。`、行首 `。`） | 全部清除 |
| `..` / `。。。` | 归一为 `——`（库内既有成品口径） |

#### B. 分段按自然语义边界

- 中文段 ≤150 字，英文段 ≤3–4 行——以手机阅读不滚屏为标准。
- 话题转换、语气停顿、场景切换处空行分段。
- 同一说话人内容过长时，在语义边界空行分段，**不必重复说话人标记**。

#### C. 交流/分享段超长块必须拆分

库内基准：纯练习稿中文段最长 39–81 字；分享日稿最长 **151 字**（9/13）；混合场稿 123–203 字。
⇒ **交流段（学员分享）单块超过 150 字必须按语义拆分**（9/19 原始单块最长 434 字，属明显未拆）。

1. 切分点**只取句末标点**（`。！？`）；单句本身超 150 字时退到 `，、；`。
2. 每段**重复 `**标签**：` 前缀**，保持「标签+内容」配对结构（下游脚本依赖此结构解析）。
3. **文字零改动**——只插入分段与标签，不改一字。
4. 拆分后必须做保真校验：

```python
def norm(t):
    t = re.sub(r'(?m)^\*\*[^*\n]+?\*\*：', '', t)   # 去标签行
    return re.sub(r'\s', '', t)                      # 去所有空白
assert norm(拆分前) == norm(拆分后)                   # 逐字一致
```

5. 拆分会让「保留率」略高于 100%（新增的是标签本身），在自检里**写明增量来源**即可。
6. **⚠️ 重建文件时必须保留前言**（2026-09-20 实测踩坑）：用正则 `^\*\*标签\*\*：` 抽段后若直接 `join` 写回，**H1 标题、「来源：」行、frontmatter 后的 `---` 分隔线会全部丢失**。正确切法：
   ```python
   m = re.search(r'(?m)^\*\*[^*\n]+?\*\*：', t)
   pre, body = t[:m.start()], t[m.start():]      # pre = 前言，原样保留
   segs = re.findall(r'(?m)^\*\*([^*\n]+?)\*\*：\n(.*?)(?=\n\n|\Z)', body, re.S)
   out = pre + '\n\n'.join(...)                   # 不要从 segs 重建全文
   ```
   写完**必须**跑 `norm(拆分前 body) == norm(拆分后 body)` 逐字校验——这次正是校验 FAIL 才发现了丢前言。
7. 单句本身超 150 字时退到 `，、；` 级再切一次；**第一轮句号级切完常残留 180–200 字段**，需第二轮。

#### D. 必须保留的东西

- **中英交织的口译现场感**：Bommie 段落里的中文口译留在同一段内，不拆出来独立成段。例外：口译内容明显属中脉空间的独立发言时，才归到中脉空间名下。
- 说话人归属不改；波密的重复修辞不改。
- 无意义的语气碎片（`对。呀他。`）保留，只做标点规范化——它们是现场真实内容。
- **垫词只清「呃／嗯／额」；「啊」整篇保留**——它是庄西口译声道的语气特征。
- **叠词／重复不去重**：`很多很多`／`一直一直`／`yes yes`／`very very`／`光光的`／`隐喻隐喻`／`允许你自己允许你自己` 一律保留（英文重复词也不做全量去重）。
- 空白转写帧 → `（此处无清晰内容）`，不删整轮。

#### E. 禁止

不重写表达、不删内容、不加原文没有的意思。有语义的回应不能清空。

#### F. 连续同说话人段的处理（历史口径差异，务必注意）

| 稿型 | 口径 |
|---|---|
| **纯练习稿（现行约定）** | **保留原始 1:1 帧结构，不做常规合并**。库内成品普遍存在连续同标签（如 20260912 有 105 处），**不视为缺陷**。 |
| 混合场稿 `### 交流` 段 | 连续同一说话人的转写帧**合并为一轮**（见 §7.3）。 |
| 形态 B（单人名英中对照块） | **保留块结构**，一个「英文 + 中文」对照单元 = 一个块，不合并成一大段。仅当相邻同说话人块的英文语义明显是同一句被切碎时才合并。 |

> 📌 旧版校对 Skill 曾写「连续同说话人段合并为一段、不重复标记」——该口径**仅适用于 2026-08 之前若干批次**，与现行入库+校对流水线（9/14–9/19）不符，**不要再据此合并纯练习稿**。

### 3.3 长文分块处理与保真校验（硬性）

单篇超过约 1200 行的转写稿，一次性处理容易在写回时被截断，**出现无声的大幅内容丢失**。

**分块规则**：

1. 按说话人标记边界把原稿切成 2–3 段（Python 按「空行 + 下一行是 `**说话人**：`」定位切点，各段字数尽量均衡）。
2. 每段单独处理，输出写到独立文件（`/tmp/YYYYMMDD_partN_out.md`），处理时**绝不读写主文件**。
3. 只有第一段含 YAML frontmatter，其余段不得凭空添加。
4. 全部分段完成后合并，检查接缝处上下文连续、无重复无缺失。

**保真率校验（每篇必做）**：

```
保留率 = 成品非空白字符数 / 原稿非空白字符数
```

| 口径 | 合格线 | 备注 |
|---|---|---|
| 全文非空白字符 | **90%–102%** | 混合场因标签合并会掉到约 94%，须与下述口径并报 |
| **剔除说话人标签行后的正文** | **≥98%** | 这才是「有没有丢内容」的真实指标 |
| 分段（`### 中脉空间` 段） | **≥99%** | 混合场专用 |

- 低于 90% 必须查明原因；低于 80% 基本可判定截断，**回滚重做**。
- 分块处理时每段单独保留率不得低于 92%。
- Get 笔记「空格代标点」形态可到 ≤103%。
- 拆分稿略超 100%（新增标签所致）须在自检**写明增量来源**。

另需逐项扫描：frontmatter 完整、说话人标记数未异常减少、无游离句号、无中文词间空格、无多余空行。

### 3.4 硬约束

- 修正用**逐条替换 + 命中计数**的脚本做，不要手改长文件；**未命中的条目必须回看原文**（多半是引文抄错），不允许静默跳过。
- **frontmatter 必须原样保留**。历史上出现过校对后 frontmatter 被整段丢失的情况，不得重演。
- B3 收尾机械扫描（每篇必做）：小写 `i'x` → `I'x`、独立小写 `i` → `I`；硬指标**基线为 0**。
- 受保护区块（Get 笔记稿）**整节不校**：`## Source note`、`## 结构化整理`（含 `### 子节`）、`## 附：开头转写噪声（保留）`；要点清单（`- ` 行）不拆。复检脚本必须先剥离这些区块，否则误报超长段/游离句号/中文词间空格。
- 原稿缺 frontmatter 时**保持缺失**，不擅自补写，在清单「待确认」写明「本文件原稿无 frontmatter，未补写，待用户决定是否回填」。
- 说话人归属**一律不改**，唯一例外是「整篇说话人颠倒」（见 §9.1）。

## 6. 内容功能分层：引导语 / 学员提问 / 回应

Lee 口径（原话）：「**只要分清引导语、回应和学员提问就可以了。**」判层**只看语义功能**，与文件命名、场次、日期、说话人标签均无关。

| 层 | 定义 | 谁在说 | 出现在哪 |
|---|---|---|---|
| 【引导】 | 练习部分的带领语——呼吸／身体／存在的引导 | 波密（英）+ 庄西（中口译） | 纯练习文件全篇；`### 中脉空间` 段全篇 |
| 【问】 | 学员发言：提问**或分享**（本库实测**分享远多于提问**） | 学员（夜子／琦龙／lulu／无心金刚鹅／欲晓 等） | 仅在 `### 交流` 段 |
| 【答】 | 老师对学员发言的回应、点评、延伸引导 | 波密（英）+ 庄西（中口译） | 仅在 `### 交流` 段 |
| 〔过程〕 | 过程帧：点名、确认音频／画面、笑声、开场与收尾 | 双方 | 全篇零星 |

**判定规则（机械可执行）**：

1. **练习段即引导**：纯练习稿、`### 中脉空间` 段整段为【引导】，**无需逐段标注**。
2. **交流段按说话人分流**：老师（`**Bommie**`／`**中脉空间**`）→【答】；学员 →【问】。
3. **中英配对不拆层**：同一轮的英文（波密原声）与中文（庄西口译）属**同一层同一轮**，不得因语种分到两层。
4. **短应答与噪声归〔过程〕**：≤15 字短应答、笑声、点名、音频确认，**不并入相邻轮、不硬塞进三层**，保留原样。
5. **层归属看语义不看标签**：`**中脉空间**` 是账号名（见 §1.3），与层判定无关。

**〔过程〕阈值**：**≤10 非空字符**（实测敏感性：≤8→过程占 16%；**≤10→19%**；≤15→27%；≤20→34%）。阈值只影响短帧，**不影响任何长段的层归属**。

**落法（推荐，待 Lee 拍板）**：`### 交流` 段每轮加行首短标记 `【问】`／`【答】`；`### 中脉空间` 段不加标记。标记可一键剥离，**正文文字与顺序零改动**。**未拍板前不改任何正文。**

### 6.1 前置障碍：段名在四个时期各不相同（26 篇普查）

| 形态 | 引导段名 | 交流段名 | 篇数 |
|---|---|---|---|
| Get 笔记早期（2025-12 ~ 2026-03） | `## 中脉空间` | `## 交流`（仅 4/8 篇有） | 8 |
| Get 笔记中期（2026-05） | `## 练习部分` | `## 交流部分`（6/8 篇有） | 8 |

## 7. 稿源识别与档案判定

### 7.1 四种稿源形态

| 形态 | 特征 | 注意 |
|---|---|---|
| **A 会议转写** | `**Bommie**` / 口译交替，逐帧一行 | >1000 行按 3 块分块处理 |
| **B 单人名·英中对照块** | `**Elsa**：` / `**Bommie**：` 块内「英文段 + 空行 + 中文段」 | 中文不单独标说话人；保留块结构；校英文音转文为主 |
| **C Get 笔记·中英混接长行式** | 单行可达 1000 字符 | 按中英边界断行，勿整行保留 |
| **D Get 笔记·中文段落式** | 纯中文段落 | 无英文可反推，只做标点分段与明显错字 |

**形态 B 细节（2026-07 起出现）**：全文只有一个说话人标签，块内先英文、空行、再中文翻译。

- **中文翻译不单独标说话人**，不要新增 `**中脉空间**` 标记；**归属一律不改**。
- 工作量分布：① 英文音转文修正（此形态识别错误最密集，尤以身体扫描引导语为甚）；② 删「标点 + 空格」残留（如 `时间的这个工具， 比如说`）；③ 块内中文超 150 字时**在块内**插空行拆分，不加新标记。
- 说话人名：**Bommie / Elsa 均为真实人名，保留原样**。Elsa 的中文写作「艾莎」（对齐既有 `host: 艾莎` 约定），不写「爱莎」。
- ⚠️ 同批内可能并存 `**Bommie**`（英文原声场）、`**Elsa**`（Elsa 带领场）、`**中脉空间**`（分享日口译）三种标签。**不做跨文件统一**，只在汇报中提示用户拍板。

### 7.2 音源标签 ≠ 讲者身份

**第一原则（不可动摇）：练习部分的英文必然是波密，中文必然是庄西；只有互动交流环节才会出现其他同修。**

- 波密与庄西练习时**共用一个腾讯会议账号（中脉空间）**，因此原始转写发言人只有「中脉空间」一个——它是**账号名，不是讲者名**。记录中的「波密」标注是**后期排版整理时人工补上的**。
- ⚠️ 「原始转写稿」里英文也挂在 `**中脉空间**` 名下是**正常现象，不是 ASR 出错**（见 `练习记录/原始转写/2026-07/` 的 21 篇）。所谓「说话人还原」，做的正是把这部分人工补回给波密。
- 例外：两人不在一处时各用一个账号（具体账号名不必反查），此时原始记录自带两个发言人标签。

**判定捷径（无需读全文）**：

- 练习段 → **英文一律归波密、中文一律归庄西**，不必犹豫。
- 全篇只有 `**Elsa**` → **录播场**（20260708–0724 共 13 篇、908 个标签）。
- 出现 `**艾莎**` 独立发言，或第三、第四个陌生人名 → **已进入交流环节**。
- **分辨「原始稿 vs 加工稿」看英文帧挂在谁名下**：挂 `中脉空间` = 未加工的原始转写；挂 `Bommie` = 已还原的加工稿。

**处理规则**：① 标签一律不改；② 下游引用（金句卡、英语卡等）按**语义**归属：英文→波密，中文→庄西，不看标签；③ 录播场的英文块是**波密原声的合法素材源**，可直接用于「跟着波密与庄西学英语」系列；④ 引用原始归档稿时**必须先做语义归属**，不可直接沿用其标签。

### 7.3 混合场稿：`### 中脉空间` / `### 交流` 双段结构

适用 `YYYYMMDD_静心茶练习+交流.md`（`entry_kind: mixed`，15 个 frontmatter 字段）。
结构固定为：`## Source note`（保护）→ `## 原文` → `### 中脉空间`（练习/引导段）+ `### 交流`（分享段）→ `## 结构化整理`（保护，含 `### 交流线索`、`### 可引用语句`）。

**交流段处理规则**：

1. 说话人标签是**独占行**：`**夜子：**` 单独一行，内容另起。
2. 连续同一说话人的转写帧**合并为一轮**，只留一个标签。实测 20260613：156 帧 → 36 轮。
3. 轮内按 ≤150 字（容差 170）空行分段。
4. ≤15 字且以句末标点结尾的**独立短应答帧**（「谢谢。」「可以的。」「诶，没有声音。」）**单独成段**，不与前后分享正文并段。
5. 合并时**不把帧末 `。` 改成 `，`**（会造出串成长条的流水句）；只有后帧以「觉得/然后/所以/但是/但/因为/于是/同时/而且/就/又/也/而是/还」起头时才把前帧句末改逗号。
6. 垫词只清「呃」「嗯」「额」；**「啊」整篇保留**。
7. 叠词／重复一律**保留不去重**，在清单「保留」行逐条列出。

**保真率三口径（硬性）**：

| 口径 | 20260613 实测 |
|---|---|
| 全文非空字符 | 20575 → 19284（**93.7%**，差额≈120 个冗余标签行） |
| 剔除说话人标签行后的**正文**保真率 | 19183 → 18953（**98.8%**） |
| 分段保真率（`### 中脉空间` 段） | 3110 → 3124（**100.5%**） |

### 7.4 档案去重与「权威版」判定（只读分析，判完交用户拍板）

1. **判同源 → 字符 n-gram 包含度**（先剔 frontmatter／说话人标签／空白与标点），**必须 n=6 与 n=10 双口径并报**。
   - **禁用句级精确匹配**：同场异稿因断句与 ASR 差异，句级命中率会低到 0%，会造成「完全不同源」的误判。
   - ⚠️ **本库 n=6 会虚高**：静心茶每日引导话术高度重复（呼吸引导、身体扫描、整理床铺…），相邻两天可天然重合。**以 n=10 为主口径**。
   - 判读经验值（n=10）：**≥40% ≈ 同一场**；**<5% = 内容无关**；**5–40% = 需人工核**。
2. **判批次来源 → 文件 birth time（`stat -f "%SB"`）**。同年同秒批量写入的一批 = 同一次导入。命名差异通常等于导入批次差异。
3. **判「这一份对应哪一天」→ 跨日期交叉匹配**，取包含度 Top3。最佳匹配指向他日时，先分*时段词冲突*（真·不同场）还是*仅话术重合*（假阳性）。

**三条并存流水线**（各自命名、互不覆盖、同写一个目录）：

| 流水线 | 命名 | 实测生成批次 |
|---|---|---|
| 转写直出（旧） | `YYYY-MM-DD.md` | 7/31 一批 21 篇；8 月为当天 |
| 规范流水线 | `YYYYMMDD_静心茶练习.md` | 7/22(30) 之后 8/12–9/15 分批 |
| Get 笔记导出 | `YYYYMMDD_静心茶练习+交流.md`（+ 摘要） | 7/22 一次写入 70 篇 |

**同日期文件多数不是内容重复**：

| 现象 | 性质 | 处理 |
|---|---|---|
| 裸日期文件 H1 为 `静心茶练习记录 — YYYY-MM-DD`，说话人**未还原**（英文帧误记 `**中脉空间**`）、切分更碎、帧数约为练习版 2 倍 | 同一录音的**早期加工阶段** | **原始转写层**，已归档 `原始转写/YYYY-MM/` |
| 裸日期文件**无说话人标签**、`英文整段 → 中文整段`交替、含 `theme:`／会议号／章节化 H2 | AI **中英对照阅读稿** | 与逐帧转写**用途不同，不可删**；更名为 `_静心茶练习·中英对照.md` |
| `_静心茶练习+交流.md`（含 `## 结构化整理`）vs `_静心茶练习.md` | **笔记层 / 转写层**关系 | 不可二选一；引用以转写稿为准，两者并存 |
| 同日两份稿 6-gram 包含度 ≈0%（0125、0208） | **同日不同场次**（时段词证实：0125 清晨场「天还没亮」vs 下午场「下午好」） | **严禁按重复合并**；加场次标记 |

**实测（26 篇 `_练习+交流.md` × 106 篇 `_练习.md` 交叉匹配，n=10）**：17 篇与同日转写稿高度同源；**6 篇与全库任何稿件均无关（≤2.1%）= 真正的唯一记录**；3 篇需人工核。

⚠️ 时段词是判定「同日两场」的快速证据：检索 `早上好/下午好/晚上好/清晨/天没亮/晚安`。
汇报格式固定三段：**这一组是什么关系 → 权威版判给谁 → 建议动作**。移动／删除一律等用户拍板。

> ⚠️ **优先级（2026-09-18 Lee 明确）**：日期与场次归属**属背景信息，不是工作目标**。「这次资料的价值在内容，不在严格的日期和时间」。除下游引用出现明确冲突外，**不必为日期/场次归属追加工时**；判定结果记录备查即可，不作为待办。**两个账号分别叫什么，无需反查。**

### 8.3 ASR「幻听词」：同一个词在不同位置对应不同原词，只能逐处判

9/19 分享场实测：几个词全篇高频出现，但**不指向同一原词**，属 ASR 在停顿/气口处凭空插入的音节。**绝不能做全局替换**。

| 幻听词 | 实测对应的原词 | 判定方法 |
|---|---|---|
| **依依** | 自己（「谢谢依依，今天的早起」＝ thank yourself）／静心（「依依的邀请你」＝ the meditation is inviting）／老师（「依依讲了另外一个视角」）／一 一／纯噪音 | 回看**同段英文**或上下文主语 |

| **佳佳** | 姐姐（「你在接近你的佳佳」＝ your sister）／纯噪音 | 回看英文 sister |
| **西西** | 疑为「庄西」的昵称 | **保留不改**，列入待确认 |

## 9. 历史批次遗留处理经验

### 9.1 说话人整体颠倒：唯一允许改归属的情形

- 现象：整篇英文段全挂在 `**中脉空间**`、中文段全挂在 `**Bommie**`；或残留 `中脉空间-发言人3/4` 等原始标签。
- 这是**上游整理环节的映射错误**，不是校对判断。按语言机械还原：英文→Bommie、中文→中脉空间，含 `-发言人N` 归一。
- 除这种整体颠倒外，**说话人归属一律不改**。

### 9.2 单标签形态的归属处理

`**Elsa**`／`**Bommie**` 单人名块内「英文 + 空行 + 中文」时，**中文翻译不单独标说话人**，不要新增 `**中脉空间**` 标记。归属一律不改。

### 9.3 人名标签跨文件不一致时不自行统一

0822 用中文「艾莎」而 202607 同批用 `**Elsa**`——**不自行统一**，一律在清单「待确认」列出待用户拍板。

### 9.4 原稿缺结构时保持缺失

2026-08 有 3 篇（0822/0824/0825）原稿直接以 `**Bommie**：` 开头，**无 frontmatter、无 `# 标题`、无 `来源：` 行**——属上游入库时的半成品。处理原则：**不加原文没有的内容**，保持缺失，在「待确认」写明「本文件原稿无 frontmatter，未补写，待用户决定是否回填」。
