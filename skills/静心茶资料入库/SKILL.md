# 静心茶资料入库

## When to use

当 Lee 提供以下材料并要求学习、整理、入库、沉淀或后续可被觉醒教练引用时，使用本技能：

- 静心茶纪要、训练营转写、正念练习材料。
- 觉醒教练相关对话、生命体验记录、心理锚点材料。
- 与“晾晒、月光、童年小院、静心茶、山之禅、湖之禅、锋利之外、深度关系、身体感、允许发生、不急于分析”等母题相关的文本。
- Lee 明确说“这类信息存入知识库”“按静心茶机制新增到 Obsidian”“以后觉醒教练可以引用”。
- Lee 提供每天的静心茶练习、引导语、交流对话、练习感受或对静心茶产品的观察。

## Core distinction

Lee 的个人知识库按三类方向区分：

1. 数字幕僚：工作相关，围绕组织、策略、安全、迎检、AI 等工作主线反复推敲。
2. 向内看 / 觉醒教练：正念、教练对话、禅修、心理学、生命体验、心理锚点、静心茶等。
3. 文史哲兴趣：历史、文学、哲学等个人兴趣材料。

静心茶资料归入第二类“向内看 / 觉醒教练”，不要存入“数字幕僚”工作知识库。

静心茶资料的机制：生命体验 → 意象表达 → 正念语言 → 多次呈现 → 形成母题、语境和可调用话语。

原则：不要只做向量化。向量负责“找得到”，Wiki 负责“看得懂、用得稳”。

## Required storage rule

不管后续格式如何统一，每天的静心茶引导语、练习记录、交流对话都应作为独立条目存在：

1. 存入 Obsidian 知识库，保留可读、可追溯、可链接的 Markdown 条目。
2. 同步存入 Get 笔记，作为日常检索和移动端调用入口。**Get 笔记必须同步完整记录正文，原则上与 Obsidian 对应条目的 Markdown 内容一致；不要只同步短备忘、摘要或结构化提炼。**
3. 不区分“归纳总结”还是“实录”：二者的原始内容都有价值，但要在 metadata 中标明 material_type。
4. 每日条目允许在原文之后追加结构化区块，如核心主题、练习动作、对话线索、可引用语句、产品观察。

## Refined ingest strategy

静心茶入库的核心不是反复滚动“产品观察”，而是长期保存和调用内容本身。产品观察可以作为稳定背景页存在，除非产品形态、导师组合、场域机制或 Lee 的角色发生明显变化，否则不需要频繁滚动更新。

汇总纪要拆分格式：
- 标题统一为 `YYYYMMDD 静心茶练习`；若含周末分享/互动，则为 `YYYYMMDD 静心茶练习+交流`。
- 内容必须保留完整中文逐字稿。汇总纪要是重要档案，不得用整理稿、摘要稿、归纳稿替代逐字稿。
- 只删除英文原文、时间戳、AI 处理提示、任务说明、"已存入"等外壳；中文部分即使断裂、重复、转写不顺，也要尽量完整保留。
- 只有练习时，不额外标注具体说话人；可用 `## 中脉空间` 作为练习部分标题，待 Lee 确认后统一。
- 练习+分享时，练习部分用 `## 中脉空间`；分享部分用 `## 交流`，并按实际记录保留说话人。
- 清理原则是“只去外壳和非中文噪音，不摘要、不合并、不重写核心原句”；除明显标点和断行外，不主动修辞化。

优先级：

1. 内容原文层：每天的引导语、练习记录、交流对话、Lee 的感受原文，都是一等资产，必须完整保存。
2. 每日结构层：在原文后轻量标注日期、类型、主题、练习动作、身体/情绪反馈、可引用语句、相关母题。
3. 片段/引用层：从原文中抽出少量能被觉醒教练稳定调用的语句和片段，保留来源，不替代原文。
4. 母题层：只有反复出现的主题才沉淀为母题页，如观察而不卷入、茶作为媒介、冻土松动、晾晒等。
5. 产品观察层：作为“静心茶为什么这样发挥作用”的背景说明，低频更新，不作为每日滚动对象。

## Ingest layers

### 1. Daily entry 每日独立条目

每天的练习和交流应各自形成相对固定格式。具体格式以 Lee 后续指定为准；在格式未定前，使用轻量占位结构：

```markdown

source_type: stillness_tea_daily
source_date: YYYY-MM-DD
entry_kind: guidance | dialogue | reflection | product_observation | mixed
material_type: transcript | summary | original_note | mixed

- 可引用语句：
- 产品观察：
- 关联母题：
```

### 2. Raw 原文归档

完整保存原文，不急着压缩成观点。建议路径：

```text

```

若后续目录进一步规范，再迁入“向内看”下的固定子目录；在未统一前，静心茶条目先放在“向内看”知识域内，绝不放进“数字幕僚”。

每份 source 至少记录：


### 3. Fragment 片段切块

按“可被重新唤起的片段”切，不按工作知识点切。片段字段：

```markdown
## 片段：标题
- 原句：
- 关键词：
- 母题：
- 情绪底色：
- 身体/意象：
- 可调用场景：
- 来源：
```

适合片段的内容包括：

- 能独立表达一个正念动作的句子。
- 能作为觉醒教练对话引用的语言。
- 有明显意象或身体感的段落。
- Lee 的个人心理锚点或反复出现的体验表达。

### 4. Motif 母题卡

只有反复出现的主题才建母题页，避免每个词都建 topic。建议路径暂定为“向内看”知识域：

```text
/Users/lee/Obsidian/向内看/
```

后续若 Lee 指定固定母题目录，再按新目录迁移。

母题页结构：

```markdown
# 母题名

## 含义
这个母题在 Lee 的表达系统中意味着什么。

## 相关原文摘录
- 摘录 + 来源

## 适合调用的场景
- 当 Lee 谈到……
- 当对话进入……

## 相关母题
- [[静心茶]]
- [[晾晒]]
```

常见母题候选：观察、觉知、空无、中心、本质、呼吸、身体、能量、房间整理、准备、坚持、智慧、比较/冲突/对立、中立、来去、变化与不变、真实/真相、头脑讲故事、不评论/不评判、回应与反应、平静、放松、流动、净化、骨骼、睡眠、邀请而非测试、生命、存在、家、温暖、耐心。

### 5. Quote bank 可引用语句库

静心茶资料要沉淀“可被再次使用的话语”。建议路径暂定为“向内看”知识域：

```text
/Users/lee/Obsidian/向内看/觉醒教练可引用语句库.md
```

按调用场景分类：

- 当 Lee 进入分析疲劳时。
- 当 Lee 谈童年、月光、老家、心理故乡时。
- 当 Lee 谈权威、锋利、责任、系统时。
- 当 Lee 谈身体、茶、山、湖、呼吸时。
- 当 Lee 需要安放而不是解释时。
- 当 Lee 需要从“测试自己”转为“接受邀请”时。

每条保留来源，不伪造出处。

### 6. Product observation 产品观察

产品观察用于记录静心茶的底层产品形态和作用机制，属于低频稳定背景，不是每日滚动更新对象。只有当产品形态、导师组合、场域机制、交付方式或 Lee 的角色发生明显变化时，才更新产品观察。

当 Lee 提供对静心茶作为产品/场域/方法的观察时，除保留原文外，结构化时优先记录以下维度：

- 导师与产品合一：导师经历、长期练习基础、翻译/共创组合、非标准化个性产品、"把自己做成产品"。
- 场域机制：小众稳定社群、核心成员/中流砥柱、线上环坐感、熟悉度、相互支持、性别结构与传播方式。
- 引导语机制：即兴生成、翻译接力、无固定脚本、联想式/意象式/半催眠感、正念/禅修/瑜伽/脉轮语言融合。
- 互动机制：周末问答、学员故事互照、导师回应、长期修行者的稳定根基和温暖抱持。
- 茶作为媒介：降低纯静坐门槛，把沉重的观呼吸/冥想变成有动作、有感官、有日常入口的练习。
- 节奏与交付：每月 21 天、早课/回放、周末互动、休息期、回放有效期。
- 个人作用路径：缓慢内在发生、冻土松动、旧话语浮现串联、情绪波幅变窄/时间变短、直觉和体感增强、耕耘而非速效。
- 角色转变：从学员到导师班，记录忐忑、配不上感、模仿焦虑，以及主动推自己做一次有惊险感的跳跃。

### 7. Concept 少量概念沉淀

只有当材料反复形成稳定理解时，才写 concept。概念页不宜多，避免把生命材料过度理论化。

适合沉淀的概念例子：

- 观察而不卷入。
- 邀请而非测试。
- 头脑讲故事。
- 身体作为静心入口。
- 茶作为日常静心媒介。
- 晾晒作为非分析性转化。
- 产品即人 / 把自己做成产品。
- 线上环坐。
- 茶作为门槛转换器。
- 冻土松动。
- 耕耘而非速效。

## Workflow

1. 读取材料，先判断材料类型：转写、文章、对话、纪要、混合汇编。
2. 统计基本结构：日期数、篇目数、总字数、是否有明显转写噪音、是否含英文/机翻/AI 小结。
3. 输出初步发现：核心母题、表达风格、与 Lee 既有心理锚点的关系。
4. 判断处理层级：每日独立条目 / 原文归档 / 归档+片段 / 归档+母题更新 / 新增可引用语句 / 新增概念。
5. 若 Lee 说“推进/入库/存进去”，写入 Obsidian，并同步写入 Get 笔记；未确认前不要把大材料直接写入。
6. 若 Get 笔记当前未配置 API 凭据或接口不可用，仍先完成 Obsidian 入库，并在 frontmatter 中把 `stored_in_getnote` 标为 `pending`，同时明确记录“待补同步到 Get”。
7. 写入或补同步 Get 时，把 Obsidian 对应条目的完整 Markdown 全文复制到 Get；Get 标题使用 Obsidian 条目的主标题，不使用“短备忘”后缀，除非 Lee 明确要求另存摘要。
8. 写入后更新项目 memory，记录本次新增 source、每日条目、Get 笔记同步状态、母题页和引用库变化。

## Pitfalls

- 不要把静心茶材料压缩成“观点文章”，它首先是语境和体验材料。
- 不要只做向量化；纯向量召回容易丢掉语境、母题位置和适合调用的边界。
- 不要过度抽象。保留原句、身体感、意象和练习动作。
- 不要把外部老师的话直接写成 Lee 的观点；需要标明来源。
- 觉醒教练引用时要避免机械贴句，要根据 Lee 当下语境轻量化引用。
- 私密材料默认不公开分享；不生成公开链接，除非 Lee 明确要求。

## Verification

完成入库后检查：

- Raw 原文是否完整可追溯。
- 每个切片是否有来源。
- 母题页是否只收反复出现的主题。
- 可引用语句是否有场景标签。
- 是否避免把材料理论化、鸡汤化、过度解释。
