播客访谈剪辑 · 人机协作 Harness 手册

00先看结论：五条铁律

1. 文稿是唯一真相源
原始逐字稿做底稿，凡是剪掉的话都做成 Word 修订删除。切到“无标记”视图，读到的就是成片稿；音频由文稿逐字生成，两者必须逐字一致。
2. 先确认，再动音频
每轮先读回人的修改，出一张“我怎么理解、准备怎么改”的回执表，有歧义的标出来等确认，确认后才剪。动音频的成本远高于多问一句。
3. 读不到就立刻说
发现某个通道读不了批注、删除线或修订，马上停下来告诉人，并给出替代办法（比如导出 Word）。不要先去做别的，最后才提。
4. 每次出片都自检
每个剪点前后重新识别一遍，和文稿比对；只复核比上一版新增的问题。整片的音量、峰值、底噪每次都量。
5. 音频只能剪，不能改
文字只做识别纠错和加标点，不增字、不换词。人想要的原话如果节目里没有，就找最接近的一段，并如实说明。

01版本复盘：每一版解决了什么

看每一版是被什么问题推到下一版的。多数返工来自协作通道和母带处理，不来自剪辑本身。

版本输入做了什么暴露的问题 → 后来的约束
V0.1原始录音＋剪辑台本（只精确到秒、只标行首）按台本估算时长，补齐台本没覆盖的决策台本时间精度不够，一句话中间的删减剪不准 → 必须先做字级时间码
V0.2人对隐私、带货、事实疑点的决定本机字级识别 → 和台本对齐 → 剪点吸附静音 → 拼接 → 接口自检同一秒两人说话、三人重叠处、台本与音频不符 → 对齐层要处理多人同秒，手工剪点单独登记
审阅稿人要求“能批注”先出“删除线＋批注”版，被否决，改成 Word 修订模式多人交叉修改时，读者要从头读下来就是成片 → 一律用修订模式
V0.3多人在企业微信在线文档里修改在线接口读不出删除和新增 → 推断 → 被质疑 → 让人导出 Word，精确读回推断出来的结果漏掉了大量“拒绝删除＝恢复” → 禁止靠推断回读修订
V0.4人在修订稿上新增 10 条批注逐条落地，含两处只改音频的（吸气声、残字）导出的批注没有选中范围 → 按划线文字或相邻句子定位，并在回复里写明对应关系
V0.5人反馈几处“刺啦、电音”；前半段太长没有喘息查明是音量统一处理的问题，重做母带链；转场音乐从 3 处加到 7 处单遍动态响度标准化会把轻的录音来回放大、硬压 → 母带链固定为静态增益＋压缩＋兜底限幅
V0.6人新增 15 处删除；反馈转场处吞字补删；逐个查音乐接口，修吞字、残字、多余空白插音乐的接口另有一套风险 → 音乐接口单独自检
开场 V2–V5.2人的金句标注（分散在两份文档里）从精简到完整、从讲道理到跳切，迭代 6 轮精简版听不懂；句子挨得太近像在对话 → 每句补足前后文；句间 1.6 秒空档，音乐抬起
V0.7确认的开场开场和正片从原始素材一起处理、一次导出两个 MP3 直接首尾相接会让音量不一致 → 不拼接成品，从源头一次出片
V0.8主持人反馈“声音低沉、更粗糙，嘉宾像在回音壁里，不如 V0.4”测量确认是真的：V0.7 句尾回响比原声高约 3dB、高频高 2–3dB、动态被压掉约 6dB；改用“削尖峰＋轻慢压＋兜底限幅”，不降噪修刺啦用力过猛会伤音色 → 母带链以“接近原声”为验收标准，用脚本量偏差；对比前先把响度调齐
V0.9“V0.8 的结构最好，V0.4 的音质更好”，要求内容保留 V0.8、声音换回 V0.4查明 V0.4 好听是因为没压缩、音量低；但原片很轻，直接放大会硬压上万个采样点（刺啦的根因）。改为“只削最尖的峰，其余不动”，音量定 −19 LUFS，与 V0.4 同音色优先于响度 → 不为追响度加压缩；成片比常规播客小约 3dB，作为已知取舍写进交付说明
V1.0“09 很好，不动了，结尾加 10 秒左右音乐，渐弱”同一首钢琴曲的最后 11.5 秒（终止和弦自然衰减），人声结束后留 0.6 秒，比人声低 6dB，渐入 0.4 秒、最后 4 秒渐出；前面 1:13:42 与 V0.9 逐样本相同已定稿的版本只加不改 → 用逐样本比对证明前段没变；之后只出一个版本

02七道关卡（Gate）

每道关卡都有通过标准，没达到就不进下一关。弱模型最容易出错的地方，是在没过关时就继续往下做。

G1

素材盘点与决策补齐

输入
原始音频、逐字稿、剪辑台本、人的补充决定
动作
核对台本是否覆盖全片；列出台本没说清的地方：说话人标错、剪了会穿帮的句子、节目惯例环节
通过
每一处删、留都有明确决定；隐私和带货逐项有结论；估算出粗剪时长
禁止
在决策没补齐时开剪
G2

字级时间码与对齐

输入
原始音频、逐行状态表（每行保留还是删除，行内哪些字删）
动作
本机字级识别；把参考文本和识别结果分块对齐；对不上的字按前后字的时间插值
通过
对齐覆盖率 ≥ 85%；行首时间偏差中位数 < 1 秒；偏差超过 5 秒的行逐一解释
禁止
只用行首秒数去剪句中的删减
G3

剪点计算与拼接

动作
保留段的首尾吸附到 10ms 能量包络的最低点；接口加 20ms 淡入淡出，补 120ms 气口；被删部分短于 0.35 秒的不剪
通过
文稿里的每一处删除，在音频里都确实被剪掉了（逐段核验）
记录
所有手工改过的剪点写进 overrides，注明原因
G4

自检

动作
每个接口前后各 3.5 秒重新识别，和文稿比对；没通过的拉长到前后各 6–8 秒再听；本轮改过的地方逐条单独复听
通过
和上一版相比没有新增未通过项；新增的逐个说明是“识别误报”还是“真问题已修”
禁止
只报通过率，不对新增问题逐个下结论
G5

母带与音乐

动作
按固定母带链处理（见第 04 节）；转场音乐只放在话题转折处，每处用不同乐句
通过
整体响度 −19 LUFS ±0.5（V0.9 定稿，宁可小声也不压缩）；最高峰 ≤ −1.5 dBFS；需要硬限幅的样本只有几十个量级；音乐接口两侧没有吞字或多余空白
G6

配套文稿

动作
生成同版本号的修订稿：删除修订的作者写“谁剪的”，每处本轮改动都有一条批注说明，每段开头标成片时间
通过
接受全部修订后的字流和音频保留的字流逐字相等；删除作者对得上；批注没有落在删除内容里
G7

交付

动作
只出一个版本：双声道 160k（约 88MB，<100MB），直接上传出手机链接，不另出试听版；回复写清改了什么、要听哪几个时间点
通过
人不打开任何中间文件，只看回复就知道这一版的结果

03人机协作协议：文稿怎么来回

3.1 修订稿的约定

人想做什么在 Word 里怎么做机器读回时怎么理解
同意某处删除接受，或者不处理照剪
恢复某段拒绝那处删除恢复
再剪一段直接选中删掉（文档默认打开了修订）以这个人的名字记为新删除
听感问题、说明、疑问批注，不在正文里打字逐条处理，在回执表里回应
宏观意见在对话里说先确认理解，再执行
删除修订的作者名写版本号，比如“剪辑V0.2”“剪辑V0.6”，人名写真名。这样任何时候都能查到某句话是哪一轮、谁剪的。

3.2 回读通道：哪条路能读到什么

通道删除 / 新增删除线批注结论
本地 .docx（含从在线文档“导出为 Word”）可读分得清，带作者可读可读但可能没有选中范围首选
在线文档读正文接口不可用只知道“谁改过”，分不清删还是加；导入时原有修订会丢可读部分只能辅助，不能用来推断修订
智能文档（富文本页）—要解析Markdown 导出不带删除线，要读块数据里的样式读不到请人用删除线或【】写说明，别用批注
事故：一次读智能文档时，开始几分钟就发现批注读不到，却先去做了别的活，几十分钟后才告诉人，人一直白等。约束：发现读取受限 → 立刻停下告知 → 给替代方案（导出 Word 或换标注方式）。

3.3 每轮的固定节奏

读回修改→回执表（理解＋改法，歧义标“?”）→人确认→改音频＋改文稿→自检→交付＋手机链接

人两次打断过“直接开剪”，要求“先推敲文稿、列出建议和疑问，确认后再处理音频”。不过，人已经明确说过“直接开始”的，就不再重复确认。

04技术参数（可直接照抄）

环节参数说明
字级识别mlx-whisper large-v3-turbo，word_timestamps=True，condition_on_previous_text=False，用 initial_prompt 写节目名、人名和术语Apple 芯片上 2 小时音频约 17 分钟；模型放 ~/.cache，镜像源不稳就换官方源，下载完校验 SHA256
对齐按 12 行一块做 difflib.SequenceMatcher，ASR 窗口单调推进；匹配块 ≥ 2 字才采用覆盖率约 90%；对不上的字按前后字时间插值
剪点10ms RMS 包络；起点在 [−0.35, +0.04] 秒内找最低点，终点在 [−0.04, +0.35] 秒内找，取最低点 3dB 以内离原位最近的剪点落在字间停顿上
拼接接口 20ms 线性淡入淡出；接口补 0.12 秒静音；需要停顿的地方单独设 0.4–0.45 秒例如切掉吸气声、残字后
母带链（V0.9 定稿）volume 8dB → 只削最尖的峰（peak −12dB，6:1，0.5/60ms）→ 线性增益到目标 → alimiter 0.80 兜底。不降噪、不滤波、不做慢压单声道 −22 LUFS ≈ 双声道成片 −19 LUFS（与 V0.4 同音量）。V0.5–V0.7 用“降噪＋两级重压缩”、V0.8 用“轻慢压”，都让回响和粗糙感高出原声，已弃用
片尾音乐同一首曲子最后 11.5s（自 172.0s 起）；人声结束后留 0.6s；比人声低 6dB，渐入 0.4s，最后 4s 渐出选结尾气氛平静收束的段落，不用有鼓点的
音色验收原片与成片同一段话对比：句尾回响偏差 ≤ +1.5dB；2–5k、5–10k ≤ +2dB；70–200Hz ≤ +1dB；动态范围 ≥ −4dB；任意 10 秒接近满幅 ≤ 1000 个采样点V0.9：+0.2 / +0.3 / +0.3 / +0.1 / −0.2，全部合格；V0.8 勉强合格；V0.7 四项不合格
转场音乐公有领域钢琴（萨蒂《Gymnopédie No.1》Musopen 录音，维基共享资源）；每处 5.1 秒，渐入 0.25 秒、渐出 1.8 秒，比人声低 6dB；前后各留 0.25 秒每处用不同乐句，避免听着重复
开场垫乐钢琴先起 3 秒，人声进来后压到 −20dB；句间空档 1.6 秒，空档里抬到比人声低约 12dB（每个空档单独算增益）；结尾回升 4 秒渐出空档短了，几句话会听成一段连续对话
交付只出一个版本：双声道 160k（约 88MB / 74 分钟）MP3 恒定码率的大小只取决于码率，与声道数无关；192k 双声道约 107MB，超过企业微信微盘 100MB 上限

05踩坑清单：症状 → 根因 → 对策

症状根因对策
几段话里有“刺啦、电音”原片录得轻（约 −28 LUFS）但瞬间峰值高；单遍动态响度标准化随时调增益，被放大 15–19dB 且忽高忽低，响的瞬间又被硬压换成固定母带链（第 04 节）；每版统计“需要硬限幅的样本数”，正常应只有几十个
声音发粗、低沉，像在回音壁里降噪和重压缩在说话间隙把房间回响抬起来，元音被压、辅音和气声相对突出；房间声本来就重的说话人最明显不降噪；只削最尖的峰；音量保持 −19 LUFS，不为追响度加压缩；用音色验收脚本量偏差。对比前把响度调齐，越响越显得低沉
测出来“削波”，其实没有两个声道内容相同时，下混成单声道电平会 ×1.414测峰值用单个声道，或者乘 0.707
转场音乐后吞掉半个字音乐插在一句话的字中间；或者剪点落在上一个人最后一个字上音乐接口单独做多候选剪点，逐个识别比对后再选
接口留下半个字、多一个字对齐误差约 0.1–0.3 秒；逐字稿本身漏字（原音是“跟我说”，稿里没有）按字级时间＋能量包络手工定剪点，登记到 overrides；以原音为准
同一句被分给两个人同一秒有两人说话，台本只写了一行同秒多行按文本相似度分配
三人同时说话的地方剪不干净人声叠在一起，物理上分不开只能连带剪或连带留，如实告诉人，让人二选一
自检报大量“待查”识别器同音字（正念→正面）、重复输出（“松动了”×7）、窗口边界截断只看比上一版新增的；新增的拉长窗口复听后下结论
中间文件突然全没了放在 /tmp，被系统清理工作目录放项目目录下的 _work/；只有临时上传才用 /tmp
在线文档导入失败CLI 只允许读工作区和 /tmp 下的文件；文档名不能含 /先拷到 /tmp；标题里用“、”代替“/”
shell 匹配中文文件名静默失效macOS 磁盘上存的是 NFD，手写的字符串是 NFC一律用 Python os.listdir＋unicodedata.normalize

06内容判断原则

不改原话
文字只纠识别错误和加标点。可剪的口癖字用〔〕标出，剪掉后仍要能听懂。
事实要核
年代、出处要查。例：某段说正念减压创立于“上世纪五六十年代”，实为 1979 年，只剪掉这几个字；某个典故被说成“童话”，音频不改，但字幕和节目简介要写对。
隐私与带货
价格、药名、未征得同意的第三方推荐，默认删除；嘉宾的家庭和情绪细节，由嘉宾本人决定。决定写进决策表。
防穿帮
“怎么收尾？”这类会暴露录制过程的话要剪；“第一……第二……”的结构剪掉“第一”时，要么补回，要么连“第二”一起剪。
转场位置
只放在话题真正转换的地方；连续论述中间、问答之间不放。大约每 10 分钟一处。
节目惯例
删除节目的固定环节（比如推荐下一位嘉宾）之前，提醒人跟主持人打招呼，并保留原始时间，方便恢复。

07开场金句（Cold open）怎么做

轮次做法人的反馈 → 规则
1按参考节目的做法，只放嘉宾，约 60 秒“要有主持人的声音” → 三个人都要出声
2出“推荐＋精简”两个方案，精简版只截金句本身“精简方案听不懂在说什么” → 每句补足能单独听懂的前后文
3推荐表只写了编号和作用，原话要去下面查格式不对 → 推荐和备选用同一种表头：序 / 开场内时间 / 成片位置 / 时长 / 说话人 / 原话
4按“讲一个完整故事”串句子“不必是完整逻辑，可以是金句穿插；时长大致 60 秒就行” → 不追求叙事线
5人点名要一句节目里没有的原话找最接近的一段并说明；补上让这句能听懂的话
6出“跳切”和“按人连续”两版选跳切；“句子挨太近，听着像正式对话” → 句间 1.6 秒空档，空档里音乐抬起
最终形态：6 句、约 70 秒；最短的一句打头，不铺垫；嘉宾 4 句，两位主持人各 1 句，三人穿插；钢琴先起 3 秒、结尾回升 4 秒，接“大家好，欢迎来到……”。

金句标注常分散在多份文档里，人有时只写“金句”两个字。先把所有标注合并去重，再列出“标过但没用上的”，并说明为什么没用。

08弱模型执行清单（每轮照着勾）
